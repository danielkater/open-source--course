## 后端覆盖

- 两个预置案例任务差异真实存在：张晨 6 项、刘静 7 项。
- 身份类别 × 岗位类别 × 用工模式的全部 8 种规则组合。
- 创建并持久化候选人，发送 Offer 后生成任务，重复启动返回 409。
- 必需前置任务未完成时，直接调用后端也无法完成下游任务。
- 候选人提交材料进入待审核；审核无人工确认参数时拒绝执行。
- 退回需要补充说明；退回后可重新提交、审核、解锁汇总审核。
- 外服必须先接收；进度更新保存；结果回传保留待审核，外服无法代替 HR 审批。
- 所有材料与服务人工通过后，才允许最终入职；完成后状态为已入职，进度 100%。
- Agent 查询读取当前数据库，材料提交前后缺失清单和待审清单相应变化。
- 下周范围筛选严格生效，范围外候选人不会出现在该查询结果。
- 督办建议在确认前不产生通知；HR 人工确认后才写督办和站内消息，重复确认被拒绝。
- 候选人工具范围检查、工具白名单与非法确认参数检查。
- 模拟兼容 LLM 服务的 function tools 交互循环，以及显式规则降级。

## 浏览器覆盖

浏览器测试启动独立的 8001 / 5174 服务与临时 SQLite，不修改现场 Demo 的两名候选人。

完整闭环通过真实页面按钮完成：创建虚构「验收模拟王晓」→ 发送 Offer → 生成 8 项任务 → 候选人确认 Offer → Agent 查询材料并记录 4 次真实工具执行 → 提交 3 项材料 → 刷新页面验证持久化 → HR 审核材料 → 材料汇总确认 → 外服接收 2 项服务并更新进度、回传模拟结果 → HR 人工确认结果 → 最终入职进度 100% → Agent 风险督办建议 → HR 确认提醒 → 候选人收到站内消息。

## 限制与警告

- **未验证真实 LLM 供应商**：没有真实 API 密钥。本机默认规则模式；LLM 协议测试使用明确的模拟供应商响应，但其调用的业务工具仍真实访问隔离测试数据库。不能将此测试描述为真实模型调用验证。
- Starlette TestClient 对 `httpx` 有一条弃用警告，17 项测试仍通过；后续升级测试客户端时需迁移其推荐适配。Playwright 的控制台颜色环境变量警告不影响测试结果。
- 认证、真实 RBAC、多租户、真实外部服务与生产部署均不属于已完成能力，详见 README。
- 本机服务保持运行于 `127.0.0.1:5173` / `127.0.0.1:8000`；仅绑定本机地址。
